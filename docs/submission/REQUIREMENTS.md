# Hyperbloom submission review

Reviewed October 11, 2026. This package is for the finished Ozymandias experience.
The hidden Second Coming experiment is outside the entry.

## Official event requirements

The [event overview](https://hyperbloom-october.devpost.com/) accepts an interactive
web experience or polished frontend. It emphasizes user flow, visual quality,
accessibility, creative interaction, originality, and a working result. A complex
backend is not required. The formal Judging Criteria section still contains a
placeholder, so no scoring weights are assumed here.

The deadline is **October 19, 2026 at 2:00 p.m. Pacific**, also shown as 5:00 p.m.
Eastern on the public page.

The [rules](https://hyperbloom-october.devpost.com/rules) require a new project and
one project per entrant. AI-assisted development and existing libraries and
assets are allowed. Source licenses, privacy, and respectful conduct still
apply. Solo and team entries are allowed.

Eligibility on the overview is limited to students who have reached the legal
age of majority in their country of residence, with the listed territory
exceptions. The entrant must confirm eligibility and the actual team details.
The overview's informal “open to everyone” description does not override this
eligibility list.

No extra requirements were posted in the event's
[Updates](https://hyperbloom-october.devpost.com/updates) or
[Discussions](https://hyperbloom-october.devpost.com/forum_topics) when reviewed.
Deployxa has a separate prize category, but using it is not listed as a condition
for the general entry. This project does not claim that sponsor prize.

## Where the evidence is

| Event emphasis | Project evidence |
| --- | --- |
| User flow | Automatic guided reading, pause and manual steps, free exploration, and reciprocal poem-to-world selection |
| Visual quality | A rendered ruin, detailed anatomy, fractured stone, grounded contact, photographic materials, and a wide final view |
| Accessibility | Semantic text, text-only reading, keyboard controls, visible focus, motion off, device reduced-motion support, and sound off by default |
| Creative interaction | Plus markers connect parts of the ruin to exact lines, and selecting a line revisits that part of the world |
| Originality | A new literary interpretation built during this project, with outside models and materials clearly credited |
| Working result | Public demo, complete source, locked dependencies, installation instructions, automated checks, and screenshots |

This table describes the available evidence. It does not claim a complete WCAG
certification, physical-device coverage, or an originality guarantee.

## Submission materials

The [project story](DEVPOST.md) is ready to copy into the Devpost description.
The repository README, credits, license, design notes, controls, and verification
notes are included. The images folder contains real screenshots of the app.
A walkthrough is provided in [DEMO.md](DEMO.md).

Devpost's [submission guide](https://help.devpost.com/article/126-know-your-submission-steps)
lists a project name, tagline, story, technology tags, media, and links. Its
recommended gallery thumbnail is 3:2 and no larger than 5 MB. Individual
hackathons can add required fields, including a video or repository link.

The authenticated event-specific form could not yet be inspected because
Devpost was signed out in the accessible browser. A hosted video and any custom
questions therefore remain unverified. The public rules do not specify a video
length. Do not treat the walkthrough file as proof that a required video has
been uploaded.

## Before submitting

- Confirm student eligibility, age and residence requirements, and the team.
- Review the signed-in event form and answer any custom questions.
- Add the public demo and repository links, the project story, technology tags,
  thumbnail, and screenshots.
- If the form requires a video, provide a public YouTube or Vimeo link that meets
  its stated length limit. Use the real app rather than a simulated interaction.
- Review the project's source and asset attribution in the final entry.
- Complete Devpost's final submission step before the deadline and confirm the
  project is marked Submitted.

Publishing this repository and demo does not submit the project to Devpost.
